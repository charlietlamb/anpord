Each variant defines one grid column:

```ts
{ harness: "codex", model: "gpt-5.6-sol" }
```

| Field | Purpose |
| --- | --- |
| `harness` | Runs the agent and its tools |
| `model` | Selects the harness model |
| `sandbox` | Where the trial runs. Optional, defaults to `e2b` |

## Agents

| Agent | `harness` | Credential | Reports |
| --- | --- | --- | --- |
| Codex | `codex` | API key or ChatGPT | Commands, files, tokens |
| Claude Code | `claude` | API key | Commands, files, tokens |
| OpenCode | `opencode` | Auth file | Commands, files, tokens |
| Pi | `pi` | Auth file | Commands, files, tokens |
| Gemini CLI | `gemini` | API key | Commands, files, tokens |
| Qwen Code | `qwen` | API key | Commands, files, tokens |
| Cursor Agent | `cursor` | API key | Commands, files |
| FX | `fx` | AI Gateway key or ChatGPT auth file | Tool names, answer |

Each agent needs a [connection](/connections). Agents with fewer reports still use the same verifier but leave less trajectory and cost data.

For Claude Code, follow the [setup guide](/guides/claude-code) to verify one trial before comparing models.

## Models

Model ids vary by agent. Use the catalogue when choosing one:

```ts
const { models } = await anpord.evals.models({ harness: "codex" });
```

Model discovery is not required before a run. Available ids depend on the harness. Catalogues come from Anpord's Codex cache, models.dev, or a fixed list, so an empty result means that source is unavailable rather than that the harness has no models.

## Sandboxes

`sandbox` is optional. A variant that omits it runs on `e2b`:

```ts
variants: [{ harness: "codex", model: "gpt-5.6-sol" }]
```

The rest are `daytona`, `upstash`, `modal`, `cloudflare`, and `vercel`. Every trial gets an isolated workspace.

None of them can reach a service on your own machine. To test against one, see [local runs](/evals/local).

The sandbox is part of the variant, so changing it starts a new history. Name one explicitly to keep adding to an existing one.

## Compare variants

Change one field at a time:

```ts
variants: [
  { harness: "codex", model: "gpt-5.6-sol" },
  { harness: "codex", model: "gpt-5.6-terra" },
]
```

A case keeps one variant per harness, model, sandbox, profile name and simulated-user model it has run on. Changing any of them creates a new variant with its own history. A new harness version remains in the same history, and each run records the version it used. Use a [profile](/evals/profiles) to compare an agent's stock and configured forms.

## Read a variant's history

```ts
const { runs, total } = await anpord.evals.caseRuns({ caseId: "writes-hello" });
```

Runs come newest first, twenty to a page. Pass `variant` to read one variant, and `page` for older runs. `evals.runCase({ caseId, trials })` runs the case's newest version again on every variant, or on one when `variant` is given.
