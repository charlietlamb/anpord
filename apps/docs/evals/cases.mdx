An eval suite is a TypeScript object. Its prompt and variants are shared; each case supplies variables, a workspace, and one pass condition.

```ts
import { suite, repo } from "anpord";

export default suite({
  name: "api",
  source: repo("acme/api@8f31c4a"),
  prompt: "{{task}}",
  cases: [
    {
      id: "health-route",
      name: "health route",
      variables: { task: "Add a /health route that returns 200" },
      verify: "bun test test/health.test.ts",
    },
  ],
  variants: [{ harness: "codex", model: "model-id" }],
  trials: 3,
});
```

A suite's `id` is derived from its `name`, lowercased with hyphens, unless you pass one. A case id is unique within your organization and its runs are kept under it, so keep it stable.

| Case field | Purpose |
| --- | --- |
| `id` | The stable handle the case's history is kept under |
| `name` | Labels the grid row |
| `variables` | Replaces prompt variables such as `{{task}}` |
| `source` | Overrides the suite workspace |
| `prepare` | Runs typed preparation before the agent |
| `cache` | Restores and saves one prepared directory |
| `verify` | Runs a shell check after the agent |
| `user` | Makes the case a [conversation](/evals/conversations) rather than one prompt |
| `validate` | Runs code validators, model judges, classifiers, or an array of them |

Every case needs exactly one of `verify` or `validate`.

## Sources

`source` is the workspace the agent starts in. Omit it for an empty workspace, so a suite runs the same on a laptop as it does in CI:

```ts
import { files, repo } from "anpord";

source: repo("acme/api@8f31c4a");
source: files({ "src/add.ts": "export const add = () => 0;" });
```

A case-level source overrides the suite source.

## Prepare

`prepare` receives typed filesystem and process helpers. Its return value reaches the validator as `prepared`.

```ts
import type { Prepare } from "anpord";

export const install: Prepare = async ({ cached, exec }) => {
  if (!cached) await exec("npm", ["ci"], { timeoutMs: 600_000 });
  return { port: 4173 };
};
```

```ts
{
  cache: { key: "npm-lock-v1", path: "node_modules" },
  prepare: install,
}
```

## Validate

Use a validator when the check is clearer in TypeScript:

```ts
import type { Validator } from "anpord";

export const hasHealthRoute: Validator = async ({ readText }) => ({
  message: "the health route exists",
  passed: (await readText("src/routes.ts")).includes("/health"),
});
```

Import the function into the eval and set `validate: hasHealthRoute`. Anpord bundles the function and its imports with the case.

The dashboard's **Validation** panel shows the original source captured during compilation, including types, comments, and formatting. Each run keeps its own snapshot.

Capture covers the TypeScript and JavaScript in the bundle, under the eval's nearest `package.json` directory. Dependencies and anything outside it are excluded, and imported fixtures in those files come too. Keep secrets out of source files, or set `captureSource: false` on `suite` to disable capture.

Use [model judges](/evals/judges) for subjective checks, [classifiers](/evals/classifiers) when the answer is one of a fixed set of labels, or combine them with `validate: [hasHealthRoute, correctness]`.

Run every discovered `*.eval.ts` suite with `anpord eval`, or pass one file with `anpord eval ./smoke.eval.ts`.

See [variants](/evals/variants) for agents and sandboxes and [profiles](/evals/profiles) for custom harness configuration.
