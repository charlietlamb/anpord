A case describes one coding task:

```ts
{
  name: "health route",
  variables: { task: "Add a /health route that returns 200" },
  source: {
    kind: "repo",
    url: "https://github.com/acme/api",
    ref: "8f31c4a",
  },
  prepare: installDependencies,
  verify: "bun test test/health.test.ts",
}
```

| Field | Purpose |
| --- | --- |
| `name` | Labels the row in a run |
| `task` | Replaces `{{task}}` in the shared prompt |
| `source` | Supplies the starting workspace |
| `prepare` | A TypeScript function run after the workspace is ready and before the agent starts |
| `verify` | Runs a shell check after the agent finishes |
| `validate` | References a TypeScript validator in file-based evals |

Keep `name` short. Write `task` as the task, not the full agent instruction. Put shared instructions in the run prompt.

## Prepare

`prepare` is a function, not a shell string, so a step is a file and arguments
rather than a line to quote:

```ts
import type { Prepare } from "anpord";

export const installDependencies: Prepare = async ({ exec }) => {
  await exec("npm", ["ci", "--workspace", "renderer"], { timeoutMs: 600_000 });

  return { rendererPort: 4173 };
};
```

Each `exec` takes its own `timeoutMs`, so a long install does not force the
same ceiling on every other step.

What `prepare` returns reaches the validator as `prepared`, and is recorded
with the trial:

```ts
export const validateRender: Validator = ({ prepared }) =>
  fetch(`http://localhost:${prepared.rendererPort}`).then((response) => response.ok);
```

The bundled function is stored with the case and hashed into its identity, so
a rerun prepares the same way and changing it starts a new baseline.

## Source

Omit `source` for an empty workspace, or set it explicitly:

```ts
source: { kind: "empty" }
```

Use a repository for larger tasks. Pin `ref` to a commit when runs must start from the same files.

```ts
source: {
  kind: "repo",
  url: "https://github.com/acme/api",
  ref: "8f31c4a",
}
```

Use inline files for small fixtures:

```ts
source: {
  kind: "files",
  files: {
    "src/add.ts": "export const add = () => 0;",
    "src/add.test.ts": "import { expect, test } from 'bun:test';",
  },
}
```

## Setup and verification

`setup` runs after the source is prepared. A nonzero exit prevents that trial's harness from starting and fails the run. Omit it when no preparation is needed.

`verify` runs after the harness finishes. Exit code `0` passes. A nonzero exit fails when the command produced usable evidence. A verifier that cannot execute, or a test runner that reports no tests, produces a void trial. Use `set -o pipefail` in shell pipelines.

Set `verify: null` to record the trajectory without scoring the trial. Void trials do not affect pass rate or create a baseline.

### TypeScript validators

For checks that are clearer in code, export a typed function:

```ts validator.ts
import type { Validator } from "anpord";

export const hasHealthRoute: Validator = async ({ readText }) => ({
  message: "the health route exists",
  passed: (await readText("src/routes.ts")).includes("/health"),
});
```

Import and reference it directly in the case. It does not need another wrapper:

```ts health-route.eval.ts
import { defineEval } from "anpord";
import { hasHealthRoute } from "./validator";

export default defineEval({
  name: "health-route",
  prompt: "{{task}}",
  cases: [{ name: "health route", variables: { task: "Add a /health route" }, validate: hasHealthRoute }],
  tasks: [{ harness: "codex", model: "gpt-5.6-sol", provider: "daytona" }],
  trials: 3,
});
```

Run every `*.eval.ts` suite with `anpord eval`, or select this one with `anpord eval ./health-route.eval.ts`. Anpord bundles the validator and its imports, runs it after the agent, and shows the function name with the result. Use either `validate` or `verify` on a case, not both.
