<Warning>
  The SDK does not accept classifiers in `validate` yet. `classify()` builds a valid classifier, but a case that uses one fails to compile. This page describes how classifiers will decide once they are wired in.
</Warning>

Use a classifier when the answer is one of a fixed set of labels and you want to know how sure the model is. It returns a probability for each of your options instead of prose, so it is faster and cheaper than a [judge](/evals/judges) and cannot pick a label you did not declare.

```ts
import { suite } from "anpord";
import { classify } from "anpord/validators";

const routed = classify({
  name: "routed correctly",
  model: "jev-latest",
  prompt: "Which team should handle this request?",
  options: {
    returns: "Exchanges, refunds, wrong or damaged items",
    shipping: "Delivery status, delays, lost packages",
    billing: "Charges, invoices, payment problems",
  },
  expect: "returns",
  minConfidence: 0.8,
});

export default suite({
  name: "support routing",
  prompt: "My shoes arrived in the wrong size. Route this request.",
  cases: [{ id: "wrong-size", name: "wrong size", validate: routed }],
  variants: [{ harness: "codex", model: "gpt-5.6-sol", sandbox: "e2b" }],
  trials: 3,
});
```

## Classifier or judge

| | Classifier | Judge |
| --- | --- | --- |
| Returns | A label and a probability for every option | A label, a score and a written reason |
| Fails when | The wrong label wins, or the right one wins below `minConfidence` | The score is below the threshold |
| Explains itself with | The distribution over your options | A sentence |
| Costs | One classification | One model call, or a sandboxed harness session |

Use a classifier when the label settles the question: which route was taken, whether the agent attempted or refused, which of three shapes an output has. Use a judge when you need to read why.

## Deciding

A trial passes when the winning label is `expect` **and** its probability is at least `minConfidence`.

The two failures mean different things. A different label winning is disagreement. The expected label winning below the floor means the model could not separate your options, which usually means two of them overlap.

`minConfidence` defaults to `0`, so any win for the expected label passes. Raise it when a near tie should not count.

## Configuration

| Field | Meaning |
| --- | --- |
| `name` | Classifier name, unique within the case |
| `model` | Exact model identifier, such as `jev-latest` |
| `prompt` | The question the model answers |
| `options` | 2 to 255 labels, each mapped to a description or `null` |
| `expect` | The label a passing trial produces, one of `options` |
| `minConfidence` | Inclusive confidence floor from 0 to 1, default 0 |
| `timeoutMs` | Classification timeout, default 30,000, range 1,000 to 300,000 |

`classify()` rejects an `expect` that is not one of `options`.

Descriptions matter when labels are close. `{ returns: null, billing: null }` leaves the model to guess from the names. A sentence for each removes the ambiguity that causes low-confidence answers.

## Authentication

Classifiers call TypeSafe directly and need their own credential. See [connections](/connections). No harness or sandbox is involved.

## Evidence and isolation

A classifier receives the rendered case prompt and the final answer. It does not see the workspace, transcript, MCP or CLI configuration, or sandbox environment.

The evidence is passed as data, not instructions, so the agent's output cannot redirect the classification. The model generates no text, so there is no schema to violate and no refusal to parse.

If the classifier cannot be reached, the failure is recorded and the trial does not pass.

## Results

Each classification carries `name`, `model`, `choice`, `expected`, `probabilities`, `confidence`, `minConfidence`, `durationMs` and `error`. The dashboard shows the distribution where a judge would show its reason.

Changing a classifier's prompt, options or expected label changes the case definition, so later runs record a new case version. Calibrate against known inputs before setting a floor: a floor above the model's usual confidence fails every trial, including correct ones.
