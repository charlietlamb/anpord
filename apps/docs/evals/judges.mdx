title: "Model judges"
description: "Score answers with a model you choose"
---

Use code for exact checks. Add a judge for qualities such as correctness, relevance, or clarity that need interpretation. When the answer is one of a fixed set of labels, a [classifier](/evals/classifiers) decides faster and reports how sure it is.

```ts
import { suite } from "anpord";
import { judge } from "anpord/validators";

const correctness = judge({
  name: "correctness",
  harness: "codex",
  model: "gpt-5.6-sol",
  prompt: "The answer explains why the result is correct, without inventing facts.",
  expected: "2 + 2 = 4",
  choices: { correct: 1, partial: 0.5, incorrect: 0 },
  threshold: 1,
});

export default suite({
  name: "arithmetic",
  prompt: "What is 2 + 2? Explain briefly.",
  cases: [{ name: "addition", validate: correctness }],
  variants: [{ harness: "codex", model: "gpt-5.6-sol", sandbox: "e2b" }],
  trials: 3,
});
```

No Effect imports or model client setup are needed in the eval file. The judge model is independent of the variant being measured. Anpord requests the exact model you specify. An unavailable model produces an unscored judgment rather than a fallback.

## Combine checks

`validate` accepts one validator or an array:

```ts
validate: [checkToolCalls, correctness];
```

Code checks run in the case sandbox. Judges run afterward. A case passes only when its code checks pass and every judge meets its threshold. A passing judge cannot override a failed code check.

## Configuration

| Field | Meaning |
| --- | --- |
| `name` | Unique judge name within the case |
| `harness` or `provider` | Agent harness, or `provider: "openai"` for a direct model call |
| `model` | Exact model identifier |
| `prompt` | Instructions for the judgment, separate from the case prompt |
| `expected` | Optional reference answer |
| `choices` | Labels mapped to scores between 0 and 1 |
| `threshold` | Inclusive pass threshold; defaults to 1 |
| `timeoutMs` | Total judging timeout; defaults to 120,000, maximum 300,000 |

A case accepts up to 20 validators. Each judge accepts up to 20 choices. Names, prompts, and expected answers are checked when the eval compiles.

## Authentication

Agent judges use your organization's connection for that harness. A Codex judge can use a ChatGPT subscription connection and does not need an OpenAI API key. When the variant uses the same harness, the judge reuses its bound connection.

For direct OpenAI calls, replace `harness` with `provider: "openai"`. That path needs its own OpenAI credential, which [connections](/connections) covers.

## Evidence and isolation

Judges receive the rendered case prompt, final answer, and optional expected answer. They do not receive the case workspace, transcript, MCP or CLI configuration, or sandbox environment.

Agent judges start in a fresh sandbox after the case sandbox closes. They are instructed to grade only the supplied evidence. Tool use invalidates the judgment. It is detected rather than prevented by a network firewall. For tool-use assertions, keep a code validator that inspects the mock call log.

Direct OpenAI judges use structured outputs with storage disabled. Both backends validate the response against the declared choices and require a short explanation. Timeouts, refusals, invalid responses, and provider failures produce `score: null` and make the trial `void`.

## Results

Each trial's `judgments` contains `name`, `model`, `evaluator`, `choice`, `score`, `threshold`, `reason`, `durationMs`, and `error`. The dashboard shows these separately from code checks. Judge costs are marked unpriced, so a judged run's cost total is incomplete.

For the request, raw response, and provider metadata, inspect the judge entry in `trial.validations`. Invalid response text is retained even when no score can be assigned. See [validation evidence](/evals/results#validation-evidence) for capture limits and privacy settings.

Changing a judge changes the case identity used for baselines. Calibrate each judge prompt against known good and bad answers before trusting its scores. Repeat trials: model judgments can vary, even with the same model and prompt.
