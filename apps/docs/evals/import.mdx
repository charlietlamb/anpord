---
title: "Import a case file"
description: "Turn existing JSON or YAML cases into a TypeScript suite"
---

`anpord eval import` converts an existing case file into a `*.eval.ts` suite.

```bash
anpord eval import --format evals-json ./evals.json --out ./release-notes.eval.ts
```

Omit `--out` to print the suite to stdout.

| `--format` | Input |
| --- | --- |
| `evals-json` | One JSON file containing all cases |
| `yaml` | One YAML file per case, or a directory of them |

## evals-json

```json
{
  "skill_name": "release notes",
  "evals": [
    {
      "id": 1,
      "name": "Lists the breaking change",
      "prompt": "Read CHANGELOG.md and write the release notes.",
      "expected_output": "A short note naming the breaking change.",
      "files": ["fixtures/changelog"],
      "assertions": [
        {
          "text": "names the removed flag",
          "kind": "content_contains_all",
          "needles": ["--legacy", "removed"]
        }
      ]
    }
  ]
}
```

Only `id`, `prompt`, and `assertions` are required. Assertions may be structured objects or prose strings.

| `kind` | Generated check |
| --- | --- |
| `content_contains_any` | `containsAny(answer, needles)` |
| `content_contains_all` | `containsAll(answer, needles)` |
| `content_contains_none` | `containsNone(answer, needles)` |

Matching is case-insensitive. Prose assertions cannot be converted safely, so they become failing placeholders:

```ts
validate: async () => [
  /* The summary reads as though a maintainer wrote it. */
  unwritten("The summary reads as though a maintainer wrote it."),
].every(Boolean),
```

`expected_output` becomes a comment, not a check. `files` carries directory names but not their contents, so each case starts with `files({})` and a comment naming the requested fixtures.

## yaml

A directory imports all `*.yaml` and `*.yml` files, sorted by name.

```bash
anpord eval import --format yaml ./cases --out ./browsing.eval.ts
```

```yaml
name: Checkout flow
task: Open the demo storefront and pay with the test card
judge_context:
  - Reach the basket page before paying
  - Use the test card, never a real one
max_steps: 12
```

`name` and `task` are required. The task becomes the prompt. Each `judge_context` entry becomes a failing placeholder because it requires human judgment. A case without `judge_context` gets one placeholder asking for a pass condition.

`max_steps` becomes a comment because Anpord does not cap agent steps. YAML cases use `files({})` because the format carries no source files.

## Finish the suite

1. Run the import and review its output.
2. Replace each `files({})` with fixture files or a [repository source](/evals/cases).
3. Choose the harness, model, and sandbox.
4. Replace every `unwritten(...)` placeholder with a real check.
5. Run the generated suite with `anpord eval ./suite.eval.ts`.

The command reports converted and unconverted assertions on stderr. Invalid files fail by path, case, and field. A directory is never partially imported.
