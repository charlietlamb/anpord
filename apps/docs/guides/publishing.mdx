---
title: "Publish prompt changes"
description: "Add, test, and promote a version"
---

Saving content creates a version. Promoting it changes what a channel returns.

## Add a version

```ts
const candidate = await anpord.prompts.update({
  id: "coding-agent",
  content: "Read the repository first. {{goal}}",
  config: { temperature: 0 },
  message: "Inspect before editing",
});
```

No channel moves. Pass `config` when the prompt uses it, since an omitted value is stored as an empty object.

## Test the content

```ts
const prompt = await anpord.prompts.get({
  id: "coding-agent",
  version: candidate.version,
});

await anpord.evals.start({
  cases,
  prompt: prompt.content,
  tasks,
  trials: 3,
});
```

The version number selects the exact candidate before `evals.start`. The run receives its content by value. Prompt `config` is not passed to the coding harness.

## Promote it

```ts
await anpord.prompts.promote({
  id: "coding-agent",
  channel: "production",
  version: candidate.version,
});
```

Promoting to a new channel creates it. Channel readers update through the SDK cache refresh, not synchronously with promotion.

To roll back, promote an earlier version to the same channel. Updates through the public SDK and API append versions instead of changing earlier content.

## Use the CLI

```bash
anpord push coding-agent - -m "Inspect before editing" < prompts/coding-agent.md
anpord promote coding-agent --to production --at 7
```

`push` never promotes and stores an empty config object. Use the SDK or API when the prompt has versioned config.
