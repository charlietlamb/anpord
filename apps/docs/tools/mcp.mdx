title: "MCP server"
description: "Use evals and prompts from an MCP client"
---

Connect to the hosted server:

<CodeGroup>

```json Claude Desktop
{
  "mcpServers": {
    "anpord": { "url": "https://mcp.anpord.com/mcp" }
  }
}
```

```bash Claude Code
claude mcp add --transport http anpord https://mcp.anpord.com/mcp
```

</CodeGroup>

The server uses OAuth 2.1. Your browser opens for sign-in and approval, so the MCP configuration does not contain an API key. Eval reads need `evals:read`; starts and reruns need `evals:write`. Prompt reads need `prompts:read`, updates need `prompts:write`, and promotions need `channels:write`.

## Eval tools

| Tool | Purpose |
| --- | --- |
| `list_eval_runs` | List a page of runs, newest first |
| `list_eval_models` | List models available to a harness |
| `start_eval_run` | Start cases across variants |
| `get_eval_run` | Read cells, trials, and comparisons |
| `get_eval_cell_history` | Read previous results for a cell |
| `rerun_eval_cell` | Repeat one cell in a new run |

`start_eval_run` returns an id immediately. Poll `get_eval_run` until its status is no longer `running`.

`list_eval_runs` returns `runs` and `next`. Pass `next` as `cursor` for the following page.

## Prompt tools

| Tool | Purpose |
| --- | --- |
| `list_prompts` | List up to 100 prompts |
| `get_prompt` | Resolve prompt content by channel or version |
| `list_versions` | Read version history |
| `update_prompt` | Append a version |
| `promote_prompt` | Point a channel at a version |

Creating and archiving prompts are not exposed. `update_prompt` stores an empty config object, so use the SDK or API for prompts with versioned config.

Adding a version does not change a channel. Test the candidate with an eval, then call `promote_prompt` after review.
