---
title: "CLI"
description: "Run eval files and manage prompts from a terminal"
---

The CLI runs TypeScript eval files, reads prompts, adds versions, moves channels, and generates variable types.

## Install

<CodeGroup>

```bash npx
npx anpord --help
```

```bash global
npm install -g anpord
anpord --help
```

</CodeGroup>

Set `ANPORD_API_KEY` before running a command.

## Commands

| Command | Purpose |
| --- | --- |
| `anpord eval [file] [--fail-on <gate>] [--no-wait] [--json]` | Run a TypeScript eval suite and wait for it |
| `anpord list [--json]` | List up to 100 prompts |
| `anpord get <id> [--json] [--channel <name>] [--at <version>]` | Read content, a channel, or a version |
| `anpord versions <id>` | Print version history as JSON |
| `anpord push <id> <content> [-m <message>]` | Append a version |
| `anpord promote <id> --to <channel> --at <version>` | Move a channel |
| `anpord generate [--out <path>]` | Generate variable types for up to 100 prompts; `gen` is an alias |
| `anpord --completions <shell>` | Print completions for zsh, bash, or fish |

Prompt content goes to stdout:

```bash
anpord get support-reply > prompt.txt
anpord push support-reply - -m "Shorter opening" < prompts/support-reply.md
anpord promote support-reply --to production --at 7
```

Run every eval suite in the repository:

```bash
anpord eval
```

Pass a file to run one suite: `anpord eval ./evals/smoke.eval.ts`. Every case,
task, and trial in a suite is scheduled concurrently, with each sandbox
provider enforcing its configured concurrency limit.

The command waits for the run, draws the grid as cells settle, and exits
nonzero when a cell regresses against its baseline.

| Option | Purpose |
| --- | --- |
| `--fail-on` | `regressed` by default; `unscored` also fails a cell with no scored trials, `never` reports without gating |
| `--no-wait` | Start the run and print its id |
| `--json` | Print the finished run instead of the grid |

A run that fails outright is reported whatever the gate, because that is the
sandbox rather than the result.

`push` does not promote or accept config. Use the SDK or API for prompts with versioned config.

<Note>
`--at` selects a prompt version. `--version` prints the CLI version.
</Note>

Failures exit nonzero without a stack trace. Status messages go to stderr.

| Variable | Purpose |
| --- | --- |
| `ANPORD_API_KEY` | API key |
| `ANPORD_BASE_URL` | API origin, defaulting to `https://api.anpord.com` |
| `ANPORD_WEB_URL` | Where a GitHub check links to, defaulting to `https://anpord.com` |
| `GITHUB_TOKEN` | Optional. With `GITHUB_REPOSITORY` and a sha, `anpord eval` posts a check named `anpord` on the commit |
