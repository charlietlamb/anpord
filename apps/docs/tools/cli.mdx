## Install

<CodeGroup>

```bash npx
npx anpord --help
```

```bash global
npm install -g anpord
anpord --help
```

</CodeGroup>

Set `ANPORD_API_KEY` before commands that call Anpord. `--help`, `--version`, `eval import` and `eval --local` work without it.

## Commands

| Command | Purpose |
| --- | --- |
| `anpord eval [file] [options]` | Run eval suites and wait for their batches |
| `anpord eval import --format <format> <path> [--out <file>]` | Turn a case file a team already wrote into a suite |
| `anpord connectors <subcommand>` | Connect the credentials evals use |
| `anpord list [--json]` | List up to 100 prompts |
| `anpord get <id> [--json] [--channel <name>] [--at <version>]` | Print a prompt's content, from a channel or a version |
| `anpord versions <id>` | Print version history as JSON |
| `anpord push <id> <content> [-m <message>]` | Add a version |
| `anpord promote <id> --to <channel> --at <version>` | Point a channel at a version |
| `anpord generate [--out <path>]` | Write variable types for up to 100 prompts |
| `anpord --completions <shell>` | Print completions for zsh, bash or fish |

## Run evals

```bash
anpord eval
anpord eval ./evals/smoke.eval.ts
```

With no file, the CLI finds every `*.eval.ts` under the current directory (skipping `node_modules`, `dist`, `build` and hidden folders) and runs them one after another. Each suite file starts one batch: one run per case per variant, each with the suite's number of trials. The command waits for the batch and applies the gate. In an interactive terminal the grid updates as trials finish. Otherwise it prints the final grid once.

| Option | Purpose |
| --- | --- |
| `--fail-on` | Gate, `failures` by default: fail when any run fails or has a trial that did not pass. `strict` also fails when a run or trial is missing or unfinished. `never` ignores trial results |
| `--timeout` | Seconds to wait per batch, default `1200`. A timeout fails the command but does not cancel the batch |
| `--output` | Write a JSON report with each file's batch ID, batch and problems |
| `--no-wait` | Start each batch and print its ID and runs, without waiting |
| `--json` | Print each finished batch as JSON instead of the grid |
| `--local` | Run each case once on this machine instead of in a cloud sandbox, using the suite's first variant, so a verifier can reach a service on `localhost`. With an API key, the batch is recorded and credentials are leased from your organization. Without one, nothing is sent. See [local runs](/evals/local) |

Under every gate, a batch that fails to start, fails, or times out fails the command.

`anpord eval import` reads an existing case file (or a directory of them) and prints a suite, or writes it with `--out`. It converts the mechanical assertions and leaves prose ones failing until someone writes the check. It reports how many of each on stderr. See [importing a case file](/evals/import).

## Connect credentials

`anpord connectors add <integration>` connects a credential for the organization. It prompts for the secret, or reads it from stdin when not run in a terminal, so the secret never appears in your shell history. Pass `--default` to make it the one evals use, `--name` to label it and `--auth` to pick an auth method. Integrations that sign in through a browser are connected in the dashboard instead.

`anpord connectors integrations` lists what can be connected, `connectors list` shows what the organization has, and `connectors remove <id>` deletes one.

## Manage prompts

Prompt content goes to stdout:

```bash
anpord get support-reply > prompt.txt
anpord push support-reply - -m "Shorter opening" < prompts/support-reply.md
anpord promote support-reply --to production --at 7
```

`push` does not promote and cannot set config. Use the SDK or API for prompts with versioned config.

<Note>
`--at` selects a prompt version. `--version` prints the CLI version.
</Note>

## Output and environment

Failures exit nonzero without a stack trace. Status messages go to stderr.

| Variable | Purpose |
| --- | --- |
| `ANPORD_API_KEY` | API key |
| `ANPORD_BASE_URL` | API origin, default `https://api.anpord.com` |
| `ANPORD_WEB_URL` | Origin for batch links, default `https://anpord.com` |
| `GITHUB_TOKEN` | Optional. With `GITHUB_REPOSITORY` set, `anpord eval` posts a check named `anpord` on the commit (the PR head on pull requests) |
