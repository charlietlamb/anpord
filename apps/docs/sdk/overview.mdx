`anpord` is the TypeScript package for defining and running coding-agent evals. Suites, mocks and validators live in your repository next to the code they test.

```sh
npm install anpord
```

Start with the [quickstart](/getting-started) to define a suite and run it.

## Package exports

| Import | Use |
| --- | --- |
| `anpord` | [`suite`, `evalCase`, workspace sources and validator types](/evals/cases) |
| `anpord` | [`Anpord` client for batches, runs and results](/sdk/client) |
| `anpord/mcp` | [`server`, `tool`, `resource`](/evals/mocks#mcp) |
| `anpord/cli` | [`cli`, `command`](/evals/mocks#cli) |
| `anpord/api` | [`api`, `endpoint`, `withApi`](/evals/api-mocks) |
| `anpord/validators` | [`judge`](/evals/judges), [`classify`](/evals/classifiers), [`human`, `script`](/evals/conversations) |
| `anpord/eval` | [`compileEval`, `compileDefinition`](/guides/run-from-code) |

Definitions are plain objects and handlers are ordinary functions and promises. Mock inputs use Standard Schema for types and runtime checks (the examples use Zod). You don't need Effect or a separate model client.

## Run a suite

Keep suites in `*.eval.ts` files. The CLI compiles each one locally, including imported fixtures and validators, and starts a batch on Anpord:

```sh
npx anpord eval ./smoke.eval.ts
```

The [GitHub Action](/guides/ci) runs the same command. To start a batch from application code, [import the suite and pass it to the client](/guides/run-from-code). Each run keeps its calls, validator evidence and captured source.

## Credentials

Set `ANPORD_API_KEY` for calls to Anpord. Save harness credentials under [Settings > Harnesses](/connections), never in eval definitions. Hosted sandboxes and mocked product services need no keys of their own.

To set up an agent, start with [Claude Code](/guides/claude-code) or the [supported harnesses](/evals/variants).
