A run needs a credential for its [agent](/evals/variants) because model usage is charged to your account. Add it under **Settings > Harnesses** before the first run. Raw model keys cannot be passed through the eval API.

| Surface | Credential |
| --- | --- |
| Anpord CLI and SDK | `ANPORD_API_KEY` |
| Agent model | Saved harness connection |
| Hosted sandbox | None by default |
| Mock product MCP or CLI | None |
| [Hosted Anpord MCP](/tools/mcp) | OAuth 2.1 |

Sandboxes run on Anpord's accounts by default. Add a sandbox connection only to run somewhere you control.

## Add one

Choose **Add harness** or **Add sandbox**, pick the provider, paste the key. Secrets are encrypted on arrival and never shown again.

Agents and sandboxes are listed [here](/evals/variants).

The first connection for an integration becomes its default, and runs use defaults unless you pick otherwise. **Verify** checks a stored credential against the provider without revealing it.

## Personal or shared

Organization connections are usable by everyone. Personal ones are yours alone and take precedence for the same integration, which is how you run against your own account without changing what your team uses.

## When the harness credential is missing

```text
No credential configured for codex
```

Nothing is charged and no sandbox opens. In the dashboard the run button stays disabled and names what is missing.

A missing sandbox connection is not an error. The run uses Anpord's account for that provider.

## Rotating and removing

**Rotate** replaces the secret in place, keeping the id and default, and makes an `invalid` credential active again.

Removing one leaves past runs readable. Removing a default leaves the integration without one, so set another before the next run.
