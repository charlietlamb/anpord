title: "The evaluation grid"
sidebarTitle: "Grid"
description: "How cases and variants become results"
---

An eval is a grid. Cases are rows, variants are columns, and cells contain repeated trials.

| Part | Meaning |
| --- | --- |
| Case | A task, workspace, preparation, and validator |
| Variant | An agent, model, and sandbox provider |
| Cell | One case run with one variant |
| Trial | One isolated attempt inside a cell |

Two cases, three variants, and three trials produce six cells and eighteen sandbox sessions.

Each cell reports pass, fail, and void counts, pass rate, command spread, and determinism. Its first scored result becomes the fixed [baseline](/evals/baselines).

Changing the task, source, preparation, validator, agent, model, or sandbox starts a new cell history. Prompt changes and agent releases stay in the same history so their effect can be compared.

A run is `running`, `finished`, or `failed`. Rerunning a cell creates a new run and leaves earlier results unchanged.
