## Prerequisites

Add a [harness connection](/connections), then create an API key with `evals:write` and `evals:read` under **Settings > API keys**.

```bash
export ANPORD_API_KEY="anp_..."
```

## Install

<CodeGroup>

```bash npm
npm install anpord
```

```bash bun
bun add anpord
```

</CodeGroup>

## Define a suite

Create `smoke.eval.ts`:

```ts
import { suite } from "anpord";

export default suite({
  name: "smoke",
  prompt: "{{task}}",
  cases: [
    {
      id: "writes-hello",
      name: "writes hello",
      variables: { task: "Create hello.txt containing exactly hello" },
      verify: 'test "$(cat hello.txt)" = hello',
    },
  ],
  variants: [{ harness: "codex", model: "gpt-5.6-sol" }],
  trials: 3,
});
```

## Run it

```bash
npx anpord eval ./smoke.eval.ts
```

The CLI compiles the file locally and starts a batch. Each trial runs in its own hosted sandbox.

## Vocabulary

- **Suite:** a group of cases that share a prompt and setup. Its id is derived from its name unless you set `id`.
- **Case:** one eval. It sets up a scenario (prompt, workspace, optional prepare step) and checks the result with validators or a verifier. A case gets a new version when its definition changes.
- **Variant:** the harness, model and sandbox (plus an optional profile) a case runs on.
- **Run:** one case on one variant. A case's runs on a variant form its history.
- **Trial:** one attempt of a run, in its own sandbox. A run's pass rate is taken across its trials.
- **Batch:** the runs started together, one per case per variant, so you can compare variants side by side.

The suite above has one case, one variant and three trials, so its batch holds one run with three trials. Two cases on three variants with three trials each would be six runs and 18 trials.
